# ПАСЗИ — лабораторные работы Linux

Интерактивные практические задания по МДК.02.01 «Программные и программно-аппаратные средства защиты информации» (2 курс).

## Лабораторная №15: защита сетевого шлюза

Сценарий: [scenarios/linux-firewall](scenarios/linux-firewall)

**Учебная задача:** устранить ошибки маршрутизации и nftables в изолированном Linux-стенде из трёх сетевых пространств имён (`pc`, `fw`, `srv`). Проверка выполняется по этапам через скрипты `verify.sh`.

### Запуск в Killercoda

1. Войдите в [Killercoda Creators](https://killercoda.com/creators).
2. Привяжите GitHub-репозиторий `eedskywardd/paszi-linux-labs` (ветка `main`).
3. Выберите сценарий `scenarios/linux-firewall` и запустите тест.
4. Убедитесь, что стартовый скрипт выполнился: `cat /root/LAB_READY`.
5. Пройдите все три шага, затем выдайте ссылку студентам.

**Внимание:** сценарий загружен в репозиторий, но до тестирования в реальной среде Killercoda готовность к проведению занятия не подтверждена.

Не загружайте сюда преподавательские ответы и ключи проверки.


## Лабораторная №16: Инцидент в базе данных

Сценарий: [scenarios/database-access](scenarios/database-access)

Linux-адаптация темы «Защита информации в базах данных» на PostgreSQL. Учебная программа отдельно предусматривает изучение **MS Access**, поэтому этот сценарий не отменяет работу с механизмами MS Access.

Внутри сценария: краткий конспект, три инцидента с правами доступа, раскрывающиеся подсказки, три автоматические проверки; отчёт в Word с 1–3 участниками и скриншотом финального этапа отправляется преподавателю отдельно.

**Публикация:** в кабинете Killercoda (Creator → Repository) нажмите Sync Now, затем откройте сценарий из My Scenarios и проверьте фактический запуск. Webhook может быть не настроен. Стартовая подготовка PostgreSQL может занимать несколько минут. Проверка непосредственно в облаке ещё не проведена.


## Дополнительный мини-практикум (закрепление темы 5.1)

Сценарий: [scenarios/sql-access-mini](scenarios/sql-access-mini)

**25–35 минут.** Две автоматические проверки SQL-прав в PostgreSQL, подробная вводная шпаргалка по `psql`, `SELECT`, `GRANT`, `REVOKE`, `INSERT`, `UPDATE`, `DELETE`. Отчёт оформляется отдельно в Word на компьютере студента; требуется один скриншот успешного завершения и ФИО от одного до трёх участников.

Это дополнительное закрепление темы разграничения доступа, **не замена** официальной практической №17 по Microsoft SQL Server.

После отправки файлов в GitHub требуется вручную синхронизировать Killercoda и проверить сценарий на облачном стенде перед массовой выдачей.


## Практическая №17: защита Microsoft SQL Server

Сценарий: [scenarios/mssql-security](scenarios/mssql-security)

**По рабочей программе:** «Изучение штатных средств защиты СУБД Microsoft SQL Server», раздел 5.1. Реальный SQL Server 2022 Developer в контейнере, backend `ubuntu-4GB`.

Состав: теоретический мини-конспект с примерами T-SQL и `sqlcmd`, три инцидента по ролям и правам, три автоматические проверки, многоуровневые подсказки, сдача Word + один скриншот финального этапа. Количество участников — 1–3, только фактическое. Внутри Linux отчёт писать не требуется.

**До выдачи студентам:** в Killercoda синхронизируйте репозиторий, откройте сценарий и проверьте создание SQL Server: `cat /root/PASZI17_READY` должно показать `READY`; затем тестируйте все три этапа. Docker-образ SQL Server большой и требует не менее 2 ГБ памяти, поэтому выбрана 4-ГБ среда. Если облачный запуск не удастся, проверьте `/root/paszi17_setup.log` и журнал контейнера. Пока реальный облачный запуск не подтверждён.
