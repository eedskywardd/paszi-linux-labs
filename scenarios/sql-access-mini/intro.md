# Мини-практикум по ПАСЗИ: команды SQL и права доступа

**Продолжительность:** 25–35 минут, закрепление раздела 5.1 после лабораторной №16. Это **дополнительная** работа, а не предусмотренная программой №17 (MS SQL Server).

**Цель:** научиться читать таблицы, находить ошибки прав и исправлять их командами PostgreSQL. Работать можно одному, вдвоём или втроём — по количеству свободных компьютеров.

## Мини-конспект: команды без загадок

**Где писать команды?** Сначала в терминале Linux войдите в СУБД:

~~~bash
cat /root/PASZI_MINI_READY
runuser -u postgres -- psql -d paszi_mini
~~~

Внутри `psql`:

| Команда | Результат |
|---|---|
| `\\du` | список ролей |
| `\\dt training.*` | список таблиц |
| `\\d training.products` | столбцы таблицы products |
| `\\dp training.*` | кто имеет доступ к таблицам |
| `\\q` | выход обратно в терминал Linux |

**Прочитать данные:** `SELECT название_столбца FROM схема.таблица;`

~~~sql
SELECT id, title FROM training.products;
~~~

**Изменить права:** `GRANT` разрешает действие, `REVOKE` отменяет разрешение.

~~~sql
GRANT SELECT ON demo.items TO visitor;
REVOKE SELECT ON demo.items FROM visitor;
~~~

*Это только примеры синтаксиса с несуществующими объектами demo.items/visitor; не копируйте их как решение.*

**Чем отличаются операции:**

- `SELECT` — читать записи;
- `INSERT` — добавлять записи;
- `UPDATE` — изменять записи;
- `DELETE` — удалять записи.

Общая форма изменения данных на посторонней таблице:

~~~sql
INSERT INTO demo.items (id, title) VALUES (4, 'Пример');
UPDATE demo.items SET title = 'Новый текст' WHERE id = 4;
DELETE FROM demo.items WHERE id = 4;
~~~

**В этой лабораторной таблицы не меняйте.** Настраивайте только права. Запросы SQL обычно завершаются точкой с запятой `;`, а команды `\\d` и `\\q` — нет.

**Проверка разрешения:**

~~~sql
SELECT has_table_privilege('seller','training.products','SELECT');
~~~

`true` — право есть, `false` — права нет. Можно дополнительно выполнить проверку от имени роли: `SET ROLE seller;`, затем запрос, после чего `RESET ROLE;`.

## Инцидент

В небольшой организации неправильно настроены роли:

- `seller` — продавец, которому нужен доступ к каталогу товаров;
- `checker` — проверяющий, которому нужен доступ к заказам.

Сейчас одна роль не видит нужные данные, а другая таблица доступна не тому сотруднику.

**Условия:** использовать SQL-команды для настройки прав, не выдавать права администратора, не удалять и не менять записи. Две автоматические проверки.
