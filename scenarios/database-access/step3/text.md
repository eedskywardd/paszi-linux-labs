# Этап 3. Секретный столбец открыт оператору

Оператор теперь читает заявки. Но в corp.tickets есть поле **internal_note** с закрытыми служебными комментариями. Оно не должно быть видно оператору.

### Критерии успеха
- support_agent читает только ticket_id, client_id, status и description.
- support_agent **не может** читать internal_note или сделать SELECT *.
- Под запретом остаются добавление, изменение и удаление заявок.

Посмотрите **\d corp.tickets** и **\dp corp.tickets**. Помните: выданное раньше право SELECT на всю таблицу может раскрывать секретный столбец.

<details><summary>Подсказка 1 — принцип</summary>
Права отдельного столбца более точные, чем права всей таблицы. Широкое разрешение нужно убрать, прежде чем ограничивать чтение.
</details>

<details><summary>Подсказка 2 — что проверить</summary>

~~~sql
SELECT has_column_privilege('support_agent','corp.tickets','internal_note','SELECT');
~~~

Ожидаемый результат: false.
</details>

<details><summary>Подсказка 3 — пример синтаксиса</summary>
На посторонней таблице: GRANT SELECT (product_id, price) ON demo.products TO viewer; — права выдаются только на два столбца, а не на всю таблицу.
</details>

Нажмите **ПРОВЕРИТЬ**: система проверяет и разрешённую выборку, и запрет секретного столбца.
