# ПАСЗИ · Практическая №16
## Инцидент в базе данных: кому доступна информация?

**45–55 минут.** Один, два или три участника за компьютером — по ситуации, не обязательно втроём.

**Важно по программе.** Раздел 5.1 «Защита информации в базах данных». В программе работа №16 посвящена MS Access; этот облачный сценарий использует PostgreSQL как Linux-адаптацию темы. Особенности защиты именно MS Access разбираются отдельно.

### Короткий конспект перед работой (8–10 минут)

**СУБД** хранит данные и определяет права доступа. **Роль** — набор полномочий в базе; она отличается от пользователя Linux. **SELECT** читает строки, **INSERT** добавляет, **UPDATE** меняет, **DELETE** удаляет.

**GRANT** выдаёт право, **REVOKE** отзывает. **Принцип минимальных привилегий**: пользователь получает только права, действительно нужные для работы.

Права бывают **на всю таблицу** и **на отдельные столбцы**. Если сотруднику выдан SELECT на всю таблицу, запретить ему просмотр одного секретного столбца только новым частичным GRANT не получится: сначала надо проверить и убрать более широкое право.

**Аудит** проверяет два направления: требуемые операции действительно разрешены, а нежелательные действительно блокируются.

Пример синтаксиса на **постороннем объекте** (не готовое решение):

~~~sql
GRANT SELECT ON demo.products TO viewer;
REVOKE UPDATE ON demo.products FROM viewer;
GRANT SELECT (product_id, product_name) ON demo.products TO viewer;
~~~

### Инцидент

В сервисной организации «Гранит» произошла ошибка настройки базы данных. Оператор не может читать обращения; аудитор видит контакты клиентов вместо журнала событий; стажёру выдан лишний доступ.

| Таблица | Назначение |
|---|---|
| corp.tickets | Обращения и закрытые служебные заметки internal_note |
| corp.clients | Контактные данные (только вымышленные записи) |
| corp.security_events | Журнал событий безопасности |

**Роли:** support_agent — оператор, auditor — аудитор, trainee — стажёр.

### Как начать

Подготовка PostgreSQL при первом запуске может занять несколько минут. Проверьте:

~~~bash
cat /root/PASZI_DB_READY
cat /root/START_HERE.txt
runuser -u postgres -- psql -d paszi_lab
~~~

Ожидаемый признак готовности — READY. Если возникла ошибка, посмотрите /root/paszi_db_setup.log и обратитесь к преподавателю.

В консоли psql можно использовать **\du** (роли), **\dp corp.*** (права), **\d corp.tickets** (столбцы), **\q** (выход).

**Правила:** не удалять таблицы и роли, не подменять записи, не выдавать SUPERUSER. Исправляйте права средствами SQL.

**Сдача:** четыре автоматические проверки и короткий свободный отчёт. Скриншоты не нужны для прохождения.
