# ПАСЗИ · Практическая №16
## Инцидент в базе данных: кому доступна информация?

**45–55 минут.** Один, два или три участника за компьютером — по ситуации, не обязательно втроём.

**Важно по программе.** Раздел 5.1 «Защита информации в базах данных». В программе работа №16 посвящена MS Access; этот облачный сценарий использует PostgreSQL как Linux-адаптацию темы. Особенности защиты именно MS Access разбираются отдельно.

### Короткий конспект перед работой (10–12 минут)

**СУБД** хранит данные и разграничивает доступ. **Роль PostgreSQL** — набор полномочий в базе, а не пользователь Linux. **Принцип минимальных привилегий**: каждому сотруднику разрешают только необходимые действия.

**Команды выполняются в двух разных местах.** В терминале Linux запускают PostgreSQL:

~~~bash
runuser -u postgres -- psql -d paszi_lab
~~~

После этого появится приглашение `paszi_lab=#`. Здесь вводят SQL-запросы, а также служебные команды psql с обратной косой чертой.

| Команда в psql | Что делает |
|---|---|
| `\\du` | Показывает роли пользователей базы |
| `\\dt corp.*` | Показывает таблицы в схеме corp |
| `\\d corp.tickets` | Показывает структуру и столбцы таблицы |
| `\\dp corp.*` | Показывает выданные права на таблицы |
| `\\q` | Выходит из PostgreSQL обратно в Linux-терминал |

**Как читать SQL-команду.** SQL обычно завершается точкой с запятой `;`. Имена таблиц пишутся с указанием схемы (`corp.tickets`). Названия прав и команд можно писать заглавными буквами для удобства чтения.

**Чтение записей** (`SELECT`):

~~~sql
SELECT ticket_id, status FROM corp.tickets LIMIT 3;
~~~

Это безопасный запрос к учебной базе: он выводит два столбца, максимум три записи, и не изменяет данные.

**Выдать право** (`GRANT`), **забрать право** (`REVOKE`):

~~~sql
GRANT SELECT ON demo.products TO viewer;
REVOKE UPDATE ON demo.products FROM viewer;
GRANT SELECT (product_id, product_name) ON demo.products TO viewer;
~~~

Это **примеры синтаксиса на вымышленных объектах** `demo.products` и `viewer`, а не команды для копирования в нашу базу. `SELECT` — чтение, `INSERT` — добавление строк, `UPDATE` — изменение, `DELETE` — удаление. В последнем примере `GRANT` разрешает читать только названные столбцы.

**Как проверить, есть ли право у роли:**

~~~sql
SELECT has_table_privilege('support_agent', 'corp.tickets', 'SELECT');
~~~

`true` — чтение разрешено, `false` — не разрешено. Для проверки фактического действия можно временно переключиться на роль:

~~~sql
SET ROLE support_agent;
-- Здесь выполняют отдельный проверочный SELECT.
RESET ROLE;
~~~

**Не путайте управление правами с изменением данных.** Вот как в SQL *вообще* выглядят операции с записями, на вымышленной таблице (в этой лабораторной их не выполняйте):

~~~sql
INSERT INTO demo.products (product_id, product_name) VALUES (1, 'Пример');
UPDATE demo.products SET product_name = 'Новое название' WHERE product_id = 1;
DELETE FROM demo.products WHERE product_id = 1;
~~~

`WHERE` ограничивает изменяемые строки; без него `UPDATE` или `DELETE` может затронуть **всю таблицу**.

**Права на таблицу и на отдельные столбцы — не одно и то же.** Если роль имеет `SELECT` на всю таблицу, дополнительное разрешение на несколько столбцов не скроет остальные. Сначала нужно пересмотреть широкие полномочия.

**Аудит результата** — это две проверки: нужная операция действительно разрешена, а запрещённая действительно отклоняется.

### Инцидент

В сервисной организации «Гранит» произошла ошибка настройки базы данных. Оператор не может читать обращения; аудитор видит контакты клиентов вместо журнала событий; стажёру выдан лишний доступ.

| Таблица | Назначение |
|---|---|
| corp.tickets | Обращения и закрытые служебные заметки internal_note |
| corp.clients | Контактные данные (только вымышленные записи) |
| corp.security_events | Журнал событий безопасности |

**Роли:** support_agent — оператор, auditor — аудитор, trainee — стажёр.

### Как начать

Подготовка PostgreSQL при первом запуске может занять несколько минут. Проверьте:

~~~bash
cat /root/PASZI_DB_READY
cat /root/START_HERE.txt
runuser -u postgres -- psql -d paszi_lab
~~~

Ожидаемый признак готовности — READY. Если возникла ошибка, посмотрите /root/paszi_db_setup.log и обратитесь к преподавателю.

В консоли psql можно использовать **\du** (роли), **\dp corp.*** (права), **\d corp.tickets** (столбцы), **\q** (выход).

**Правила:** не удалять таблицы и роли, не подменять записи, не выдавать SUPERUSER. Исправляйте права средствами SQL.

**Сдача:** три автоматические проверки. После последнего успешно проверенного задания сделайте скриншот и отправьте преподавателю Word-файл с ФИО всех участников и собственным выводом. Внутри Linux отчёт писать не нужно.
