# ПАСЗИ · 2 курс · Практическая работа №17
## Расследование нарушения доступа в Microsoft SQL Server

**Тема по программе:** «Изучение штатных средств защиты СУБД Microsoft SQL Server». Время: ориентировочно 45–55 минут после подготовки стенда. Это настоящий SQL Server 2022 Developer в Docker на Ubuntu-4GB, а не PostgreSQL. Первая загрузка контейнера может занять несколько минут.

### Мини-конспект: как пользоваться командами

**SQL Server** хранит данные в базах. **Логин** позволяет подключиться к экземпляру сервера, **пользователь базы** действует внутри базы, **роль** объединяет разрешения. Учебные пользователи здесь созданы *без логина*: администратор проверяет их права через временное переключение контекста.

**SELECT** читает записи, **INSERT** добавляет, **UPDATE** изменяет, **DELETE** удаляет. **GRANT** выдаёт разрешение, **REVOKE** отзывает, **DENY** явно запрещает. Используйте **минимально необходимые права**.

В правом облачном терминале дождитесь готовности:

```bash
cat /root/PASZI17_READY
sql17
```

Ожидаемый ответ первой команды: `READY`. Команда `sql17` открывает интерактивный `sqlcmd`. В нём после запроса SQL на **новой строке введите `GO`**, нажмите Enter. Выйти: `EXIT`. Например:

```sql
SELECT name FROM sys.database_principals WHERE type='R';
GO
```

| Команда | Назначение |
|---|---|
| `SELECT name FROM sys.database_principals WHERE type='R';` | Список ролей текущей базы |
| `SELECT name FROM sys.database_principals WHERE type='S';` | Учётные записи пользователей базы |
| `SELECT * FROM sys.database_permissions;` | Записи разрешений (не полный итог прав) |
| `EXECUTE AS USER = 'имя';` | Перейти в контекст пользователя |
| `REVERT;` | Вернуться в исходный контекст |
| `GO` | Выполнить введённый пакет в sqlcmd |

**Примеры синтаксиса на вымышленных объектах** (это НЕ готовые решения):

```sql
SELECT TOP (3) item_id FROM demo.Items;
GRANT SELECT ON dbo.ExampleTable TO reader_role;
REVOKE UPDATE ON dbo.ExampleTable FROM reader_role;
GRANT SELECT (item_id, item_name) ON dbo.ExampleTable TO reader_role;
EXECUTE AS USER = 'example_user';
SELECT TOP (1) item_id FROM dbo.ExampleTable;
REVERT;
```

`GRANT SELECT (имена_столбцов)` разрешает чтение только определённых полей. Важно сначала проверить, не было ли ранее выдано более широкое разрешение на всю таблицу. Также можно выяснить разрешение **текущего** пользователя:

```sql
SELECT HAS_PERMS_BY_NAME('dbo.Incidents', 'OBJECT', 'SELECT');
```

Результат: 1 — разрешено, 0 — не разрешено.

### Инцидент «Меридиан»

Нарушены права в базе `paszi17`. Требуется восстановить принцип минимальных привилегий.

| Роль и пользователь | Должен иметь доступ |
|---|---|
| `incident_reader` → `analyst_user` | Чтение `dbo.Incidents` |
| `hr_reader` → `hr_user` | Чтение `dbo.Employees` |
| `ticket_reader` → `support_user` | Только `ticket_id`, `status`, `summary` в `dbo.Tickets` |
| `intern_user` | Только чтение `dbo.PolicyBulletin` |

**Запрещено:** удалять таблицы/данные, выдавать `db_owner`/`sysadmin`, подменять роли и обходить правила через дополнительные объекты. Используйте штатные средства SQL Server: роли, GRANT/REVOKE, проверку прав.
